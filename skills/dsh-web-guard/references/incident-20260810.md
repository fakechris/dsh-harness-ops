# dsh-web-guard — 事故复盘与设计依据（2026-08-10）

> 本文件记录"agent 无法自救重启"事故的完整复盘，以及守护方案每个设计决策的实证依据。
> 目的：未来任何 agent 遇到"重启失败/拉不起来"时，先读本文件，不要重蹈覆辙。

## 事故时间线（2026-08-10）

1. **问题提出**：用户要求"kill 掉 3080 后自动拉起来，不需要手动"。此前每次重启都失败，必须用户手动 `dsh web` 才能起来。
2. **第一次尝试**：同一条 bash 调用里 `kill + dsh web &`。结果：kill 掉宿主（agent 所在进程）→ 命令被中断（interrupted）→ 启动命令可能没执行。
3. **第二次尝试**：`launchctl submit` 一次性 job 跑重启脚本。结果：
   - `nohup: dsh: No such file or directory` —— launchd 环境 PATH 没有 `~/.local/bin`
   - 改成绝对路径 `dsh` 后：`exec: node: not found` —— launchd 环境 PATH 也没有 nvm node
   - **KeepAlive 循环**：job 启动失败→进程退出→launchd 又拉起→又失败→无限循环，且每次 kill 当前 3080 → 误杀用户手动起的进程。用户必须手动 `launchctl bootout` 才能停。
4. **正确方案**：LaunchAgent 常驻守护（PPID=1），脚本内显式 export PATH + 绝对路径 + 端口空闲才拉起。
5. **实测通过**：kill 431 → 10s 内自动拉起 3097 → HTTP 200。守护进程 PPID=1（launchd 托管）。

## 五个关键教训（设计决策的实证）

### 1. kill 自宿主 = 自杀式重启
agent 在 3080 进程内，`kill $(lsof -ti :3080)` 杀的是自己。同一命令里 kill 之后的启动逻辑不可靠。**必须带外**（系统服务管理器）。

### 2. 子进程不会"连坐死"，但会挂起
后台 `&` 子进程继承父 shell 的 stdout/stderr 管道，工具会一直等管道 EOF 才返回 → 表现为 interrupted/挂起。**必须 `>> log 2>&1 < /dev/null` 全 fd 重定向**。

### 3. launchd/systemd 环境 PATH 极简
launchd 拉起的环境 PATH 默认不含 `~/.local/bin`、不含 nvm。`dsh` 是 launcher 脚本（`exec node`），光有 `dsh` 绝对路径不够，**node 也必须在 PATH**。必须显式 export：`NODE_DIRS + /usr/local/bin:/usr/bin:/bin`。

### 4. KeepAlive 管的是进程存活，不是业务拉起
`launchctl submit` 的一次性 job + KeepAlive：脚本退出就重启 → 启动失败 → 循环。**正确用法**：守护脚本常驻（`while true`），KeepAlive 管守护本身（守护崩溃才拉起守护）；web 的拉起由循环内"端口空闲检测"驱动。这样 web 起不来只会循环重试拉起（10s 间隔），不会触发管理器级循环，也不会杀其他进程。

### 5. 端口空闲才拉起 = 与其他机制协调的关键
守护从不 kill、只在端口空闲时拉起。这样：
- 与 ab.sh switch/rollback 互补（它们 kill 后守护自动拉起新 current）
- 不误杀用户手动起的 web（用户起的也在监听，守护不动）

## 为什么之前"重启加载的代码没变"

另一个独立教训（同事故）：dsh-track 插件走 `package.json main → lib/index.js`（**构建产物**），不是 src。改 src 后不 `build`，重启加载的还是旧 lib —— 表现为"重启了但行为没变"。**改插件源码后必须 build 再重启**（`node scripts/dsh-env.mjs tsc -p tsconfig.json` + tsdown + rename）。

## 为什么不用其他方案

| 方案 | 否决原因 |
|---|---|
| `launchctl submit` 一次性 job | KeepAlive 循环 + 环境 PATH 极简（事故 3） |
| `at` 定时任务 | macOS atd 默认没跑（实测 job 排队但不执行） |
| `setsid` | macOS 无 setsid 二进制 |
| 手动 `dsh web &` | 依赖 agent shell 存活，agent 死即死 |
| 健康检查主动重启 | 会误杀运行中的 web（假死误判风险）—— 守护只做"端口无监听拉起" |
